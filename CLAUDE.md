## Commands

- `npm run dev` — dev server at http://localhost:3000 (Turbopack)
- `npm run build` — production build (also the main type/config validation step)
- `npm run lint` — ESLint 9 flat config (`eslint-config-next` core-web-vitals + typescript)
- `npm run lint:css` — Stylelint (`stylelint-config-standard`, with Tailwind v4 at-rules allowed)
- `npm run format` / `npm run format:check` — Prettier (with `prettier-plugin-tailwindcss`, which sorts classes, including inside `cn()`/`cva()`)
- `npx tsc --noEmit` — type-check only

There is no test framework set up yet.

Git hooks (Husky): `pre-commit` runs lint-staged (ESLint --fix / Stylelint --fix + Prettier on staged files; config in `lint-staged.config.mjs`), and `commit-msg` runs commitlint, so commit messages must follow Conventional Commits (`feat: …`, `fix: …`, `chore: …`).

## Stack and architecture

Early-stage job tracker app, currently the `create-next-app` scaffold plus shadcn/ui. Next.js 16.4 (App Router, `app/`), React 19.3, TypeScript strict, Tailwind CSS v4.

**Next.js docs are bundled locally** in `node_modules/next/dist/docs/` (`01-app/` for App Router). Check them before using any Next.js API — this version differs from older training data.

**Rendering model (`next.config.ts`)** — these flags change how every route must be written:

- `cacheComponents: true` — data fetching is dynamic by default; opt into caching with the `"use cache"` directive plus `cacheLife` / `cacheTag`. Routes prerender a static shell and stream dynamic parts, so dynamic data access must sit inside `<Suspense>`. Route segment configs like `export const runtime` / `dynamic` / `revalidate` are not supported; see `02-guides/migrating-to-cache-components.md`.
- `partialPrefetching: true` — `<Link>` prefetches only the static shell by default; use `prefetch={true}` per link to fetch more. Requires `cacheComponents`.
- `experimental.agentFeedback: true` — `next dev` rewrites the managed block in `AGENTS.md`; don't hand-edit it.

**Typed route helpers** — `LayoutProps<"/">` / `PageProps<"/route">` are global types generated by Next (into `.next/types`) and used without imports.

**Styling** — Tailwind v4 is loaded through a Turbopack CSS loader rule (`@tailwindcss/turbopack` in `next.config.ts`), not PostCSS; there is no `postcss.config` or `tailwind.config`. All theme tokens (oklch CSS variables, light + `.dark` class variant, radius scale) live in `app/globals.css` under `@theme inline`, `:root`, and `.dark`.

**UI components** — shadcn/ui with the `base-nova` style (`components.json`), which builds on **Base UI** (`@base-ui/react`) rather than Radix. Add components with `npx shadcn@latest add <name>`; they land in `components/ui/`. Variants use `class-variance-authority`; class merging uses the `cn` npm package (`lib/utils.ts` just re-exports it, and generated components import from `"cn"` directly). Icons: `lucide-react`.

**Path alias** — `@/*` maps to the repo root (e.g. `@/components/ui/button`, `@/lib/utils`).
